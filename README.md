# planning-kit — Claude 기획 코치 플러그인

> Claude를 기획 코치로 만듭니다. 질문 몇 개에 답하면 프로젝트 폴더에 기획 문서 체계가 세팅되고,
> 요구사항 정리부터 화면설계서까지 코치와 대화하며 만듭니다. 터미널·코딩 지식이 필요 없습니다.

## 설치 (5분)

1. 아래 파일 목록에서 **`planning-kit.plugin`** 을 내려받습니다.
2. Claude 데스크톱 앱(Cowork 모드) 대화창에 파일을 끌어다 놓고 **저장(Save)** 을 누릅니다.
3. 기획 문서를 쌓을 폴더를 연결하고 이렇게 말하세요 — **"새 프로젝트 기획 시작하자"**

자세한 사용법은 [`시작-안내.md`](./시작-안내.md) 를 참고하세요 (일상 사용 문구 · 효율적으로 쓰는 법 · 기능과 구조 · FAQ).

## 구성

| 파일 | 설명 |
| --- | --- |
| `planning-kit.plugin` | 플러그인 본체 (코치 스킬 3종 + 기본 킷 + 선택 팩 6종 + 독립 검증자) |
| `시작-안내.md` | 받는 분을 위한 시작 가이드 |

## 버전 히스토리

### v0.4.0 (2026-08-12)
- **요구사항 분석 코치 신설(스킬 3번째)** — "요구사항 정의서 분석해줘"·"RFP 읽고 정리해줘"에 반응. 받은 문서(정의서·RFP·기능 명세·엑셀 요건 목록 등 형식 무관)를 읽어 **①설계 범위 In/Out/보류 ②요건 초안(원본 ID 추적) ③확인 필요 목록(불명확·모순·누락·읽기불가) ④결정 필요 항목** 네 가지만 산출한다. 추측 금지·설계 금지·모순은 양쪽 인용, 마지막은 **범위 선언 3요소**(어디까지 읽었나·어떻게·안 읽은 것)로 끝맺어 1단계부터 누락이 드러나게 했다.
- **FEAT(기능 목록) 문서 유형 추가** — 개발 착수 전 기능 범위 합의·산정·구현 누락 점검용. 다만 **파생물**로 못 박았다: 파생 선언 헤더 필수, `FEAT-##`는 문서 로컬 ID(요건 인덱스 비추적), 근거 REQ·POL·SCR·DEC를 반드시 표기, 원본을 먼저 고치고 다시 파생. 양식 `docs/FEAT.md` 추가.
- **정합성 검사에 FEAT 파생물 가드 추가** — 파생 선언 헤더 존재 + 참조 ID 실재를 검사(끊긴 참조 = 실패). FEAT가 원본과 조용히 어긋나는 것을 자동으로 잡는다.

### v0.3.0 (2026-08-12)
- **배포 정의 갱신 — 배포 = PDF 빌드 + git 커밋.** 릴리스 컷(절차 B)에 배포 커밋 단계 신설: 커밋 대상 명시(동결본·베이스라인·다음 라인 프로토타입·라이브 설계서 — PDF 제외), 메시지 규약 `chore(release): vX.Y 동결 + vX.Z 라인 개시`.
- **git 위생 규칙 신설** — `git add -A` 금지·파일 명시 add·커밋 전 스테이징 육안 확인, 정규식 일괄 편집 등 파괴적 작업 직전 안전핀 커밋, 논리 단위 1개 = 커밋 1개.
- **기획자 눈 확인 게이트 신설(절차 A-3.5)** — 화면설계서 파생 전, 근거가 된 프로토타입 변경을 기획자가 브라우저로 확인해야 진행("확인할 화면 목록" 제시 → "확인했다" 수신 → 파생).
- **범위 선언 3요소** — 검증·조사·전수 확인은 결과보다 먼저 **대상·방법·제외**를 보고. 선언 없는 '전수 조사' 서술 금지(범위를 좁혀 놓고 전수라 말하는 실수의 구조적 방지).
- **독립 검증자(verifier) 에이전트 추가**(화면설계서 팩) — "verifier로 검증해줘"로 호출. 읽기 전용·검사 불가=실패·통과에 근거 필수·전수 주장은 범위부터 검증. 작업 세션과 분리된 맥락에서 직접 실행해 보고.

### v0.2.3 (2026-08-07)
- **화면설계서 상태 칩 어휘 3단계 확정** — `초안`(0.x 신규 화면) · `개정`(해당 버전 변경 화면) · `확정`(1.0 이상 정식 배포본). 컬러는 버전과 무관하게 단일 유지(흑백 기조), 구분은 텍스트로만.
- **메이저 버전 전환 기준 신설** — 첫 정식 배포(고객 승인)에 0.x → 1.0 컷. 이후 1.x 변경 화면은 `개정`, 다음 정식 배포에서 `확정`.
- 버전 라벨 잔존 검증 grep에 **단어 경계 규칙** 추가 (`v0.1`이 `v0.10`을 오매치하는 문제 방지).

### v0.2.2 (2026-08-07)
- **프로토타입 수정 2트랙 작업 리듬 도입** — 별도 말이 없는 프로토타입 수정은 **탐색 수정**(프로토타입만 + 경량 검증 + 한 줄 기록)이 기본값. docs→화면설계서→배포본 전체 파이프라인은 "파생까지"·"동기화"·"버전 업데이트" 명시 시에만 실행. 확인용 수정 한 번에 풀 파이프라인이 돌아 시간·토큰이 과다 소모되던 문제 해결.
- 탐색 수정이 5건 이상 쌓이면 코치가 일괄 동기화를 먼저 제안.
- `시작-안내.md`에 **'기능과 구조'** 섹션 추가 (코치 스킬 2종 · 기본 킷 · 선택 팩 6종 · 전체 흐름).

### v0.2.1 (2026-07-30)
- 최초 공개 배포 — 코치 스킬 2종(기획 시작 · 기획 진행) + 기본 킷(기획 방법론 5대 원리 · 문서 양식 세트 · 행동 규칙) + 선택 팩 6종(화면설계서 · 의사결정 로그 · 셀프 검토 · UX 리뷰 · 자동 점검 · 컨플루언스 동기화).
