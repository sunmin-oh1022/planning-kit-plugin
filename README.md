# planning-kit — Claude 기획 코치 플러그인

> Claude를 기획 코치로 만듭니다. 질문 몇 개에 답하면 프로젝트 폴더에 기획 문서 체계가 세팅되고,
> 요구사항 정리부터 화면설계서까지 코치와 대화하며 만듭니다. 터미널·코딩 지식이 필요 없습니다.

## 설치 (5분)

1. 아래 파일 목록에서 **`planning-kit.plugin`** 을 내려받습니다.
2. Claude 데스크톱 앱(Cowork 모드) 대화창에 파일을 끌어다 놓고 **저장(Save)** 을 누릅니다.
3. 기획 문서를 쌓을 폴더를 연결하고 이렇게 말하세요 — **"새 프로젝트 기획 시작하자"**

자세한 사용법은 [`시작-안내.md`](./시작-안내.md) 를 참고하세요 (일상 사용 문구 · 효율적으로 쓰는 법 · 기능과 구조 · FAQ).

### v0.6.0 (2026-08-19)
- **⚠️ 배포 사고 수정 — 신규 프로젝트에 킷 저자의 작업 일지가 복사되던 문제.** `kit-install core` 가 `core/` 를 통째로 복사하는데 `core/DEVLOG.md` 에 킷 자신의 개발 기록(2026-06~07)이 들어 있어, 세팅하는 모든 프로젝트가 남의 일지를 받고 있었다. gitignore 는 커밋만 막을 뿐 파일 생성을 막지 않아 드러나지 않았다. 저자 기록을 저장소 루트로 분리하고 `core/DEVLOG.md` 는 빈 템플릿으로 되돌렸다.
- **같은 사고 2건 추가 발견·수정** — 배포 직전 페이로드를 훑다가 팩에서도 같은 유형을 찾았다. `ux-review` 팩의 `docs/UX-REVIEW.md` 에 킷 저자의 2026-07-13 UX 검토 원문이, `spec-verify` 팩의 `docs/REVIEW.md` 에 2026-06-24 검증 결과가 실려 있어, 해당 팩을 설치하는 모든 프로젝트가 남의 검토 기록을 받고 있었다. 둘 다 저장소 루트로 분리하고 페이로드는 빈 템플릿으로 교체.
- **`kit-install core` 가 업그레이드에 안전해졌다 (★ 중요).** 종전에는 기존 프로젝트에 다시 설치하면 채워 넣은 `docs/` 를 통째로 덮어썼다 — 요건·화면·회의록이 전부 사라지는 동작. 이제 **사용자 내용(`docs/` · `ROADMAP.md` · `CLAUDE.md` · 기록물 · `.gitignore`)은 있으면 보존**하고 **킷 메커니즘(`rules/` · `scripts/` · 안내 문서)만 갱신**한다. 실제 운영 프로젝트(문서 3,968줄) 복사본으로 58개 파일 전수 비교해 1바이트도 바뀌지 않음을 확인했다. 덮어써야 할 때만 `--force-docs`.
- 예시 파일(`SCR-001.md` · `FLOW-001.md`)은 같은 폴더에 이미 실물이 있으면 넣지 않는다 — 화면 13개인 프로젝트에 예시가 끼어 추적 검사에 끊긴 참조로 잡히던 문제.
- **일정 단일 진실 `docs/SCHEDULE.md` 신설.** 오픈일자가 PRD 마일스톤 칸·ROADMAP 목표 일자·FEAT 범위 요약·RELEASE 에 흩어져, 한 곳만 갱신되고 나머지가 조용히 낡았다(같은 파일 안에서도 — 마일스톤 칸은 새 날짜, 배경 칸은 옛 날짜인 상태가 실제로 발생). 이제 **절대 일자는 SCHEDULE 에만 있고 다른 문서는 마일스톤 키(`mvp`·`v1.0`)로만 부른다**. 마일스톤 키는 REQ·INDEX 의 `milestone` 필드와 같은 값이라 새 ID 체계를 만들지 않았다.
- **정합성 검사에 '일정 누출' 가드 추가** — 설계 문서에 '오픈·출시·런칭' 옆에 날짜가 붙어 있으면 경고한다. 결정 근거 일자(`2026-07-31 확정·DEC-008`)·회의일·폐기일은 '일어난 일의 기록'이라 대상에서 뺐다. 실측: 운영 프로젝트에서 34곳 검출, 빈 양식에서 오탐 0.
- **비기능 요건을 REQ 로 일원화.** PRD 와 REQ 두 곳에 같은 표가 있었고, 라벨 사전은 그중 **ID 가 없는 쪽(PRD)** 을 수치 출처로 지목하고 있었다(진실 주장 3곳). PRD 는 다룰 분류 체크만 하고 값을 갖지 않는다 — ID 가 있어야 TC 추적이 끊기지 않는다.
- **ROADMAP 을 순수 진척판으로.** 고유하게 갖는 것은 진척 판정·의존/블로커·리스크 셋뿐이고 나머지는 참조다: 범위(Out of scope·Backlog) → PRD · KPI 목표 → PRD · 미결 결정 → DECISIONS · 일자 → SCHEDULE. 종전 ROADMAP 의 Out of scope 표는 PRD 보다 칸이 하나 많아(결정 일자) 실무의 손이 그쪽으로 가 PRD 가 낡는 구조였다.
- **`HISTORY.md` 를 커밋 대상으로 전환.** 버전별 변경 이력은 개발·신규 합류자도 알아야 하는 사실인데 gitignore 라 같은 저장소를 받은 사람이 볼 수 없었다. DEVLOG(일자별 작업)·SHARE(외부 공지)는 개인 기록이라 그대로 제외.
- **`kit-install migrate <project-dir>` 신설** — 0.5.x 프로젝트에서 고칠 곳을 파일·줄 단위로 찾아 보여준다. **읽기 전용이라 아무것도 고치지 않는다**(사람=판단 / AI=탐지). 흩어진 오픈 일자를 모아 SCHEDULE 마일스톤 표에 넣을 후보로도 제시한다.
- **요구사항 분석에서 도메인별 기능 목록이 나온다.** `requirements-intake` 산출이 4가지 → 5가지(⑤ 도메인별 기능 목록). FEAT 양식을 화면 단위 → **도메인 → 기능 그룹 2단**으로 바꿔 화면이 정해지기 전에도 쓸 수 있게 했다(초안 모드 · 화면 칸은 `(미정)`). 화면이 붙으면 같은 파일의 화면 칸만 채운다 — F-ID 는 바꾸지 않는다(산정·WBS 번호가 끊긴다).
- 정합성 검사가 **근거 REQ 없는 기능 행**을 실패로 잡는다(지어낸 기능 = 요건 누락 신호). 도메인 분할(`docs/domains/`)의 REQ·SCR 참조도 해석한다.

### v0.5.1 (2026-08-14)
- **코치의 브리핑 기록 `.planning/status.json` 신설(요청 ③ 완료)** — 복귀 브리핑 직후와 세션 종료 시, 코치가 방금 말한 **지금 단계·다음 할 일·지금 할 수 있는 것**을 기록으로 남긴다. 외부 도구(ReleaseKit Studio 등)가 이 기록을 읽어 **코치와 같은 말**을 표시하기 위한 것. 기록이 없어도 상대는 자체 판정으로 동작하므로 실패해도 사용자 흐름을 막지 않는다.
- **형식은 지시문이 아니라 스크립트가 보장** — `scripts/coach-status.py` 신설. 코치가 매번 손으로 JSON 을 쓰면 형식이 흔들리고, 흔들리면 읽는 쪽이 "형식 문제"로 표시한다. 필수 필드·단계 값 범위·원자적 교체를 기계적으로 강제하고, **필수 항목이 하나도 없으면 아예 쓰지 않는다**(읽는 쪽이 '쓸 수 없는 기록'으로 버리는 상태를 만들지 않기 위해).
- **인계 문구 품질 검사** — 다음 할 일·지금 할 수 있는 것은 상대 도구의 인계 버튼이 **코치에게 그대로 되돌려 보내므로**, "검토 필요" 같은 명사형이면 고리가 끊긴다. 명령형 완성 문장이 아닌 것 같으면 경고한다.
- 기록의 킷 버전은 `.planning/kit.json` 에서 읽어 채운다(추측하지 않음). `status.json` 은 로컬 전용이라 커밋되지 않는다.

### v0.5.0 (2026-08-14)
- **프로젝트 구성 기록 `.planning/kit.json` 신설** — `kit-install` 이 설치를 마칠 때마다 "어떤 킷 버전·어떤 팩으로 세팅됐는지"를 프로젝트 안에 남긴다. 외부 도구(ReleaseKit Studio 등)가 플러그인 설치 경로를 뒤지지 않고 프로젝트만 읽으면 되도록 하기 위함. `core` 는 파일을 만들고 `pack` 은 팩 이름을 **누적**하며, **각 명령이 자기 작업을 성공적으로 끝낸 뒤에만** 기록한다(부분 성공도 사실대로 남는다). 임시 파일 후 원자적 교체라 중간 상태의 반쪽 파일이 남지 않는다.
- **킷 버전 단일 소스 `VERSION` 파일 도입** — 종전에는 버전이 플러그인 매니페스트에만 있어 `kit-install` 이 읽을 수 없었다(개발 저장소와 배포본의 경로가 달라 어느 한쪽에서만 동작). 이제 버전을 올릴 곳은 `VERSION` 하나이며, 빌드가 플러그인 매니페스트를 자동으로 맞추고 불일치 시 빌드를 실패시킨다.
- **`.gitignore` 에 `.planning/` 규칙 추가 — `kit.json` 만 예외로 공유** — 세션마다 바뀌는 관측 기록(`status.json` 등)은 제외하되, 구성 기록은 커밋한다. 커밋하지 않으면 세팅한 사람 컴퓨터에만 파일이 있고 같은 레포를 받은 다른 사람은 전부 폴백 판정으로 떨어지기 때문. ⚠️ 이 규칙은 `.planning/*` 로 써야 한다 — `.planning/` 로 디렉터리를 통째로 제외하면 git 이 하위 파일을 되살리지 못해 예외가 무효가 된다(실측 확인).
- **`doctor` 에 구성 기록 표시** — 설치된 킷 버전·팩 목록·세팅 시각을 함께 진단한다.
