# 사용자 언어 사전 — 내부 용어 번역표

원칙: 왼쪽 용어는 사용자 대면 발화에 등장하지 않는다. 항상 오른쪽으로 번역한다.
사용자가 먼저 내부 용어를 쓰면 따라 써도 된다 (그 사용자에겐 이미 멘탈 모델이 있다는 신호).

## 프로세스 (Phase → 일 언어)

| 내부 | 사용자 언어 |
| --- | --- |
| Phase 0 환경 셋업 | 시작 준비 |
| Phase 1 docs 채움 | 무엇을 만들지 정리하기 |
| Phase 2 검증 | 빠진 곳 점검하기 |
| Phase 3 프로토타입 | 화면 움직임 확인하기 |
| Phase 4 화면설계서 | 화면설계서 만들기 |
| Phase 5 릴리스 | 전달하고 다음 버전 열기 |
| 6 Phase 프로세스 | 기획이 진행되는 순서 |
| SSOT / 단일 진실 | 같은 내용은 한 곳에만 적는 원칙 |
| 정합성 검사 (check-docs) | 문서들이 서로 어긋나지 않았는지 자동 점검 |

## 문서 (파일명 → 역할)

| 내부 | 사용자 언어 |
| --- | --- |
| PRD.md | 프로젝트 정의 (무엇을 왜 만드는지) |
| glossary.md | 용어 사전 |
| REQ.md / REQ-### | 요구사항 (목록/번호) |
| POL.md | 정책·규칙 |
| IA.md | 메뉴 구조 |
| SCR-### / 상태 매트릭스 | 화면 정의 / 화면별 상태표 |
| FLOW-### | 사용자 흐름 |
| TC.md / GWT | 검증 기준 ("이렇게 하면 이렇게 돼야 한다" 목록) |
| INDEX.md | 전체 목차 |
| DECISIONS.md | 결정 기록 (확정/미결) |
| DEVLOG.md / HISTORY.md | 작업 일지 |
| REVIEW.md | 검토 결과 기록 |
| ROADMAP.md | 진척 지도 |
| CLAUDE.md | (언급할 일 없음 — "프로젝트 설정"으로만) |
| 프로토타입 (HTML) | 눌러볼 수 있는 화면 시안 |
| 화면설계서 (designspec) | 화면설계서 (그대로 사용) |

## 도구·스킬 (내부명 → 제안 화법)

| 내부 | 사용자에게 제안할 때 |
| --- | --- |
| spec-self-review | "가볍게 검토해드릴까요? — '검토해줘'" |
| spec-verify-loop | "꼼꼼히 교차검증할까요? — '○○ 부분 검증 돌려줘'" |
| designspec-version-update | "문서가 바뀌었으니 화면설계서 버전을 올릴까요?" |
| release-cut | "전달 끝났으면 다음 버전 라인을 열까요?" |
| decision-sync | "회의록에서 결정사항을 정리해둘까요?" |
| ux-review | "이 화면 UX 관점에서 검토해볼까요?" |
| intent-capture | "요청 의도를 먼저 정리해볼게요" |
| git 스냅샷/커밋 | 저장해뒀어요 · "되돌려줘"로 복구 가능해요 |
| 팩 (pack) | (언급 금지 — 기능이 "준비돼 있다/없다"로만) |

## 상태 표현

| 내부 상태 | 사용자 언어 |
| --- | --- |
| TODO 플레이스홀더 잔여 N | 아직 빈칸 N곳 |
| check-docs ✗ | 서로 어긋난 곳 발견 (고칠 수 있어요) |
| check-docs ! (warning) | 채우는 중인 곳 (정상) |
| 미결 (DECISIONS) | 아직 결정 안 된 것 |
| 동결본 | 이미 전달한 확정본 (건드리지 않는 것) |
| 절차 A / 절차 B | 화면설계서 업데이트 / 다음 버전 열기 |
