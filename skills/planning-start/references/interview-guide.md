# 인터뷰 가이드 — 질문과 구성 매핑

원칙: 질문은 **프로젝트의 성격**을 묻는다. 도구·팩·프로파일 이름은 질문에도 보고에도 등장하지 않는다.

## 질문 (한 폼에 묶어 제시)

| # | 질문 (사용자 언어) | 형식 | 용도 |
| --- | --- | --- | --- |
| Q1 | 무엇을 만들려고 하세요? 한두 문장이면 충분해요. | 자유 입력 | 프로젝트명·PRD 한 줄 정의 시드, CLAUDE.md TODO |
| Q2 | 이 기획은 어떤 상황인가요? | 선택: ① 혼자 아이디어를 검증하는 중 ② 팀과 함께 실무 프로젝트 진행 ③ 품질·검증 요구가 높은 프로젝트 (규제·대규모) | 기본 구성 결정 (아래 매핑) |
| Q3 | 화면설계서를 PDF 문서로 만들어 공유할 일이 있나요? | 예/아니오/모르겠어요 | designspec 추가 여부 |
| Q4 | 회의가 잦거나 결정이 자주 바뀌는 편인가요? | 예/아니오 | decision-log 추가 여부 |
| Q5 | 회사 위키(Confluence)에 문서를 올리나요? | 예/아니오 | confluence-sync 추가 여부 |

- Q3에 "모르겠어요" → 일단 제외하고, 나중에 화면설계서가 필요해지는 시점에 코치가 추가를 제안한다 (그때도 팩 이름 없이).
- Q2가 ③이면 Q3~Q5와 무관하게 전체 구성이므로 나머지는 Q1만 받아도 된다 — 폼에는 모두 노출하되 매핑에서 무시.

## 답변 → 설치 구성 매핑

| 조건 | 설치 |
| --- | --- |
| 항상 | `core` |
| Q2=① | core만 (이하 Q3~Q5로 개별 추가) |
| Q2=② | + `designspec` + `spec-verify` |
| Q2=③ | + 전체 팩 (`designspec` `spec-verify` `decision-log` `ux-review` `automation-hooks` `confluence-sync` 중 confluence-sync는 Q5=예일 때만) |
| Q3=예 | + `designspec` (미포함 시) |
| Q4=예 | + `decision-log` |
| Q5=예 | + `confluence-sync` |

## CLAUDE.md TODO 채우기

| TODO 자리 | 채우는 값 |
| --- | --- |
| 프로젝트명 | Q1에서 추출 (없으면 폴더명) |
| 한 줄 정의 | Q1 답변을 다듬은 한 문장 |
| Core/App 모듈 구조 | 기획 전용 프로젝트: "해당 없음 — 기획 문서 프로젝트" |

## 완료 보고 시 구성 요약 (사용자 언어 번역표)

| 내부 구성 | 사용자에게 말할 때 |
| --- | --- |
| core | 기획 문서 틀 (정의·용어·요건·정책·화면·검증) |
| designspec | 화면설계서를 만들고 PDF로 내보낼 준비 |
| spec-verify | 마감 전 "검토해줘"로 자동 점검 |
| decision-log | 회의·결정 기록을 한 곳에 정리 |
| ux-review | 화면·플로우의 UX 검토 |
| automation-hooks | 위험한 변경을 자동으로 막는 안전장치 |
| confluence-sync | 위키(Confluence)로 문서 보내기 |
