# docs/meetings/ — 회의록·논의 기록 원본 보관소

> 회의록·일정 공지·협의 문서는 **불변 원본(immutable input)** 으로 여기에만 쌓는다.
> 상태(결정됐나/누가/언제까지)는 이 폴더가 아니라 [`docs/DECISIONS.md`](../DECISIONS.md)가 단일 진실.

## 규칙 3가지

1. **파일명**: `YYYY-MM-DD_제목.md` (예: `2026-07-29_고객사미팅_오픈일정.md`). 날짜 접두사가 정렬이자 최신 판별 기준.
2. **원본은 고치지 않는다.** 사후 수정 대신 추기(append)만. 결정 결과를 회의록 본문에 되적지 않는다 — 회의록마다 "결정 추적표"를 두면 빈 채로 방치된다(안티패턴).
3. **저장 직후 `decision-sync`.** 파일을 넣고 "결정 반영"이라고 하면 결정 추출 → DECISIONS.md 갱신까지 자동. 이 한 마디가 유일한 관리 행위다.

## 왜 이렇게 하나

결정 기록이 회의록 추적표·정책 문서 본문·검토 로그·로드맵 4곳에 흩어지면, 어느 하나만 갱신되고 나머지는 낡는다(실제 사례: 결정 후 2주간 대시보드가 미결로 표시). 원본(여기)과 상태(DECISIONS.md)를 분리하면 낡을 수 있는 곳이 한 곳으로 준다.
