# DECISIONS — 의사결정 로그 (단일 진실)

> 프로젝트의 모든 미결·확정 의사결정의 **상태 단일 진실(SSOT)**.
> 회의록·POL·REQ·REVIEW 본문에 결정이 적혀 있어도, **이 표가 갱신되기 전까지는 '미결'로 취급**한다.
> 갱신은 `decision-sync` 스킬로: 회의록·일정 문서를 주고 "결정 반영"이라고 하면 된다.

## 운영 규칙

1. **한 결정 = 한 행.** 회의록마다 추적표를 두지 않는다(빈 표 방치 방지) — 원본은 `docs/meetings/`에 쌓고, 상태는 여기서만 관리.
2. **행 삭제 금지.** 결정돼도 상태만 `✅`로 바꾸고 이력을 보존한다. 대시보드·보고서 등 소비자는 `⬜/🟡`만 필터해서 쓴다.
3. **결정권자·기한 없는 미결은 표류한다.** 신규 행 추가 시 두 칸을 비우지 않는다 — 모르면 그것 자체를 안건(owner 배정)으로 올린다.
4. 결정 시 기입: 상태 `✅` + 결정 내용·일자 + 반영 대상(POL/REQ/SCR 등) → 해당 문서의 `(협의 필요)` 제거 → DEVLOG 한 줄.
5. `ROADMAP.md` §6(decision parking lot)은 본 표의 **미러(요약)** — 값이 다르면 본 표가 정답.

## 상태·분류 기호

- 상태: `⬜ 미결(내부 결정 대기)` · `🟡 외부 답 대기` · `✅ 결정됨` · `⛔ 폐기(결정 불필요)`
- P(우선순위): `P1` 산출물 확정을 막음(최우선) · `P2` 외부 리드타임 큼 · `P3` 표시·운영(결정 빠름)
- 분류: `내부`(우리/고객사가 정함) · `외부`(협력사·타 시스템 답을 기다림)
