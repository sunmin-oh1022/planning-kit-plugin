# prototype/ — 화면 프로토타입 산출물

> 화면설계는 사용자 콘솔(USER)·관리자 콘솔(ADMIN) 중심. 홈페이지(HOME)는 기획자 설계 범위 밖.
> 기준 문서: `docs/screens/SCR-*.md` · `docs/POL.md` · `docs/glossary.md` (단일 진실). 본 폴더는 그 시각화/구현.
> **다른 프로젝트로 재사용**하려면 → [`화면설계서-가이드.md`](화면설계서-가이드.md)(프로젝트 비종속 컨벤션 추출본) + `_template.designspec.html` 복사.

## ✏️ 직접 수정하기 (기획자용 — 문구 수정은 AI 없이)
화면설계서·프로토타입은 **순수 HTML**이라 텍스트 에디터(VS Code)로 직접 고친다. 문구 수정에 매번 AI를 부를 필요 없음.

**① 어떤 파일을 고치나**
| 고치고 싶은 것 | 파일 (VS Code로 열기) |
| --- | --- |
| 화면설계서 PDF의 글자 | `console/[{DOMAIN}] 화면설계서.designspec.html` (ADMIN은 `admin/[{DOMAIN2}] …`) ← 이 **소스**를 고침 (`.pdf`는 직접 수정 불가) |
| 동작 프로토타입의 글자/숫자 | `console/[{DOMAIN}] 프로토타입_v0.1.html` (ADMIN은 `admin/[{DOMAIN2}] …`) |
| 개정이력 표(버전 추가) | 위 `.designspec.html` 안의 `<div class="page revision">` 블록 |

**② 글자 고치는 법** — VS Code에서 파일 열고 `Cmd+F`로 바꿀 문구 검색 → 태그(`<...>`) 사이의 글자만 고치고 저장.
- 예) `참여기관 / 팀 수량` → `참여기관 / 팀` 으로: 그 글자를 찾아 고치면 끝.
- ⚠️ **건드리지 말 것**: `<style>…</style>`(맨 위 CSS), `class="..."`, 태그 구조(`<div>`, `<td>` 등), 맨 아래 `<script>`(렌더용). 글자만 고친다.

**③ 미리보기 (빌드 없이)** — `.html` 파일을 더블클릭 → 크롬에서 열림.
- 프로토타입: 그대로 동작(메뉴 클릭 전환). 고치고 **새로고침**하면 반영.
- 화면설계서: 페이지들이 세로로 쌓여 보임(인쇄 전 확인용).

**④ PDF 다시 뽑기 (별도 단계 — 필요할 때만)** — HTML 수정·브라우저 확인은 ①~③에서 충분히 끝낸 뒤, **전달용 PDF가 필요한 시점에만** 따로 빌드한다(HTML 수정 ≠ PDF 빌드). 터미널에서 **한 줄**:
```bash
cd "<프로젝트 루트>"
bash prototype/build-all.sh          # ★ USER·ADMIN 화면설계서 PDF 전부 한 번에
```
- 버전 올릴 때: `bash prototype/build-all.sh v0.2` (→ `*_v0.2.pdf` 생성, 기존 v0.1 보존)
- 특정 하나만: `bash prototype/build-pdf.sh "prototype/console/[{DOMAIN}] 화면설계서.designspec.html" "prototype/console/[{DOMAIN}] 화면설계서_v0.1.pdf"`
- (프로토타입은 빌드 불필요 — `.html` 저장 후 브라우저 새로고침이 끝.)

**⑤ 개정이력 추가** — `.designspec.html`의 revision 표에서 `<tr>…0.1…</tr>` 줄을 복사해 한 줄 추가하고 버전/내용/날짜/작성자만 바꾼다. (이 페이지는 기획자가 직접 관리)
- 표기 규칙: 화면 속 날짜/시간은 `docs/glossary.md` 날짜·시간 규칙(POL-016)을, 문서 작성/개정일자는 `YYYY-MM-DD`를 따른다.

> 구조를 바꾸거나(새 화면 추가 등) 잘못 고쳐 깨졌을 때만 AI에게. 문구·숫자·표 행 수정은 위 방법으로 직접.

## 파일명 · 버전 체계 ★ (중요 — 화면설계 ↔ 프로토타입 버전 매칭)
산출물은 **도메인 단위 화면설계서(멀티 페이지)** + **페이지 단위 프로토타입** 두 종류. 같은 도메인·버전으로 매칭한다.

| 산출물 | 파일명 | 단위 | 비고 |
| --- | --- | --- | --- |
| 화면설계서 (소스) | `[{DOMAIN}] 화면설계서.designspec.html` | 도메인 1개 = 1 파일 | 화면 추가 시 이 파일에 페이지 섹션 추가 |
| 화면설계서 (전달본) | `[{DOMAIN}] 화면설계서_v0.1.pdf` | 도메인 1개 = 1 PDF | 소스에서 렌더. 초안 = v0.1, 수정 시 사용자 요청으로 v0.2… |
| 프로토타입 (동작) | `[{DOMAIN}] 프로토타입_v0.1.html` | **도메인 1개 = 1 파일(단일 페이지 앱)** | 사이드 메뉴로 화면 전환. 화면별 해시 `#dashboard`·`#gpu`·`#users`. 버전은 화면설계서와 일치 |

- **버전 매칭 규칙**: 프로토타입 `_vX.Y` = 그 화면이 정의된 화면설계서 `_vX.Y`. 버전 업은 **사용자가 명시 요청할 때만**(예: "v0.2로 올려줘") 새 파일 생성. 기존 버전 파일은 보존(이력).
- 화면설계서 1페이지의 **Page Info에 매칭 프로토타입 파일명**을 적어 문서↔프로토타입을 추적 가능하게 한다.
- 관리자 콘솔은 `[{DOMAIN2}] …` 접두사로 동일 적용.

> 화면설계서 앞부분(공통): **p1 표지(.cover) · p2 프로젝트 개요(.summary, docs/PRD.md 기준) · p3 개정이력(.revision) · p4 정보구조 IA(.ia, docs/IA.md 도메인 테이블)**. 이후 화면별 2p. → **`prototype/_template.designspec.html`** 가 이 앞 4페이지+스타일의 템플릿(IA는 도메인 테이블만 채움). 새 도메인 화면설계서는 이를 복사해 IA 테이블·화면 페이지를 추가한다.
> ★ **개정이력(.revision) 페이지는 기획자가 직접 관리** — 자동으로 행 추가/수정하지 말 것(HTML에도 주석). 프로토타입은 사이드 메뉴로 화면 전환(SPA).

> USER 콘솔 설계 대상 화면 3개 모두 완료(v0.1). `[{DOMAIN}] 화면설계서_v0.1.pdf` = **표지 1p + 화면 3×2p = 7p**. {도메인 기능}·{도메인 기능}·외부 연동 시스템는 SSO 외부 링크라 화면 설계 대상 아님.
> ★ **페이지 높이는 콘텐츠에 따라 자동 확장** — A4 세로(210mm)에 욱여넣지 않는다. 가로만 297mm 고정. `build-pdf.sh`가 페이지별 높이를 측정해 정적 @page 크기로 단독 렌더 후 합친다. **높이 맞추려 CSS를 반복 조정하지 말 것.**

## 화면별 2종 산출물 (컨벤션)
| 산출물 | 용도 | 형식 |
| --- | --- | --- |
| ① 동작 프로토타입 | 리뷰·의사결정용. 브라우저에서 바로 열람 | 정적 HTML + 약간의 JS, 흑백 와이어프레임. 상단 데모 컨트롤로 권한·상태(6종) 전환 |
| ② 화면설계서 | 고객사 전달용 문서 | A4 **가로**. 피그마 화면설계 스타일 |

### 화면설계서 레이아웃 (피그마 스타일 — 고정)
- **표지(커버)**: 문서 첫 장 = `.page.cover`(브랜드 컬러 풀블리드, 조직 로고·Confidential·대각 스트릭·타이틀·Team/Author·Copyright). 빌드 버퍼는 0.4mm로 작아 흰선 없이 꽉 참.
- **목업 창 고정 크기**: `.win{ height:138mm; display:flex; flex-direction:column }` — 가로는 `.mock`(69%), **세로 138mm 고정**. 정보가 적어도 납작해지지 않고 실제 화면처럼 보임(내용은 상단부터, 사이드바는 전체 높이). 138mm = 가장 풍부한 화면(대시보드 ~135mm)이 안 잘리는 값.
- **공통 정의 페이지**(앞부분, IA 다음 `.page`): 문서 전체에 적용되는 cross-cutting 기준 3종 — ① **권한 매트릭스**(역할 × 기능·데이터 노출/실행) ② **데이터 표시 규칙**(숫자·단위·빈값/미제공·날짜 POL-016) ③ **메시지 톤·유형 공통 범례**(성공/실패/확인/경고/안내 × 표시 방식). 화면별 유효성·메시지 표는 이 범례를 따른다.
- **상단바**: `Screen Path / Status`(브레드크럼) · 상태칩(버전) · `Screen ID`(SCR-ID)
- **화면별 1페이지**: 좌 **목업 70%**(흑백, 영역마다 **포인트 컬러 넘버 뱃지 ❶~❽**, 뱃지는 **좌측 거터**에 배치해 콘텐츠와 겹치지 않게) + 우 **Description 30%** —
  `뱃지 + 영역/컴포넌트명`(헤딩) → 글머리기호로 **동작·인터랙션** → 그 아래 글머리기호로 **데이터/표시 규칙**(세부는 `ㄴ`). 협의 항목은 포인트 컬러.
- **화면별 2페이지**: 화면 기본 정보 + **컴포넌트 액션 정의** + **유효성·메시지 정의** + 상태 매트릭스(6) + 화면 내 기능 플로우. 각 섹션은 `h2{margin-top:22px}`로 **한 줄 정도 여백**을 둔다.
  - **컴포넌트 액션 정의**(`<h2><span class="n">액션</span>…`): 인터랙티브 컴포넌트별 `컴포넌트(❶~번호) · 트리거 · 동작·결과 · 검증·예외 · 관련 POL` 표. 목업 번호 뱃지와 1:1 매칭. Description("무엇을 보여주나")과 역할 분리("누르면 어떻게 되나"). 협의 항목은 `.opn`.
  - **유효성·메시지 정의**(`<h2><span class="n">검증</span>…`): 케이스별 `케이스 · 조건/결과 · 메시지 문구(실제 카피) · 표시 방식(토스트/다이얼로그/인라인/배너) · 관련 POL` 표. 공통 톤은 ‘공통 정의’ 페이지 범례를 따름.
- 포인트 컬러 `--pt`(현재 `#E5403A`), 상태칩 `--chip`(`#2563EB`). 목업/플로우 본문은 흑백.
- **뱃지 잘림 방지**: 클리핑 컨테이너(`.win`)에 `overflow:hidden` 금지. 뱃지는 거터에 두고 `box-shadow:0 0 0 2px #fff` 링.
- **고정 폭 · 세로 자동(최소 210mm)**: `.page` = `width:297mm; min-height:210mm; padding:8mm 11mm`. 가로 고정, **세로는 최소 210mm(A4 가로 1장) ~ 무제한 자동 확장**. 짧은 페이지(개정이력 등)도 210mm로 채워져 납작해지지 않고, 내용이 많으면 그 이상으로 늘어남. `@page{margin:0}`. PDF는 `build-pdf.sh`가 페이지별 높이로 렌더. **A4 세로에 맞추려 CSS 반복 조정하지 않는다.**
- **플로우 폭 규칙**: SVG `width:<viewBox px>; max-width:100%`로 **1:1 렌더**(폰트 = 다른 표와 동일 10px). 폭은 내용만큼만 — 짧으면 좁게, 길면 viewBox를 넓혀 시트 폭까지 사용하되 `max-width:100%`로 과대 방지. `width:100%`는 텍스트가 같이 커지므로 금지.
- 인쇄 시 배경색이 나오도록 `print-color-adjust:exact` 필수.

빌드 도구 없음 — 더블클릭으로 열린다. mock 데이터 사용.

## 화면 크기 정책 (POL-017) ★ 모든 프로토타입 적용
> 이 정책은 **프로토타입 HTML(브라우저 화면)** 기준. 화면설계서 PDF는 별개(297mm 고정 인쇄 시트).

| 구분 | 디자인 기준 폭(작업 캔버스) | **최소 보장 폭**(이하 깨지면 안 됨) | 참고 높이 |
|---|---|---|---|
| **PC(데스크톱)** | 1440px | **1280px** | 800px+ |
| **모바일** | 375px | **360px** (320px 미지원) | 640px+ |

- **폭이 binding 기준**(높이는 세로 스크롤 허용). 브레이크포인트: `≤768` 모바일 · `769~1279` 축소/태블릿 · `≥1280` 데스크톱 풀.
- **콘솔(USER·ADMIN) = 데스크톱 우선**: 최소 1280px. 1280 미만에서는 상단에 **‘데스크톱 권장’ 안내 배너**(`.vp-warn`, `@media (max-width:1279px)`) 노출, 모바일 전용 레이아웃은 미지원. → `<body>` 직후 `.vp-warn` div + 관련 CSS가 두 콘솔 프로토타입에 적용돼 있음.
- **홈페이지(HOME) = 완전 반응형**(360px~). HOME 프로토타입 신규 제작 시 모바일까지 대응.
- 콘솔 컨테이너는 `.app{max-width:1180px}` 중앙 정렬(최소 1280 뷰포트 안에 들어오는 콘텐츠 컬럼). 신규 프로토타입은 1440 기준으로 디자인하되 1280에서 깨지지 않게.
