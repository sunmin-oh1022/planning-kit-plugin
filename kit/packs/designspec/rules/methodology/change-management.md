# rules/methodology/change-management.md — 형상 관리 (산출물 버전 동기화 가드레일)

> **단일 진실(SSOT)은 docs.** 프로토타입이 먼저 바뀌어도 화면설계서는 docs에서 파생한다.
> 형상 관리에는 **별개의 두 작업**이 있다 — 혼동 금지:
> - **절차 A · 버전 업데이트** — 트리거: (업데이트된 프로토타입 근거) **"화면설계서 버전 업데이트"**. docs 동기화 후 designspec 파생.
> - **절차 B · 릴리스 컷(버전 라인 개시)** — 트리거: **"vX.Y 배포했고 오늘부터 vX.Z로"** 류 형상 관리. docs 동기화와 무관, 버전 라인만 분기·동결.

## 왜 (배경)
프로토타입을 vX.Y로 다듬는 동안 새로 정리된 용어·규칙·요건(예: 용어 일괄 치환, 신규 정책)이 docs에 반영되지 않은 채 화면설계서만 갱신되면, docs·프로토타입·화면설계서가 어긋난다. 산출물 3종의 단일 진실 관계를 고정한다:

- **프로토타입** = 탐색·검토용 동작 산출물 (먼저 바뀔 수 있음)
- **docs**(REQ·IA·POL·glossary·SCR·TC·FLOW) = **단일 진실(SSOT)**
- **화면설계서**(`*.designspec.html` → PDF) = docs를 시각화한 **파생물**

핵심 규칙: 변경은 항상 **프로토타입 → docs → 화면설계서** 순서로 흐른다. **프로토타입에서 화면설계서로 바로 가지 않는다.**

## 절차 A — 화면설계서 버전 업데이트 (docs 동기화 후 파생)
1. **docs 먼저 동기화** — 프로토타입 vX.Y에서 추가/구체화/변경된 요건·용어·규칙을 docs에 반영한다. `rules/methodology`의 작성 규칙과 5대 원리(단일 진실·ID 추적·모든 상태·Out of scope·GWT) 준수.
   - 용어 일괄 치환 (예: 구용어→신용어) — glossary·_labels 기준.
   - 신규/변경 **정책은 POL**, 요건은 **기존 REQ 본문 보강** (신규 REQ ID 남발 금지), 화면 구조는 **IA·SCR**, 흐름은 **FLOW**, 용어는 **glossary** 에 반영.
2. **정합성 검증** — `bash scripts/check-docs.sh` 가 ALL GREEN(종료코드 0). REQ↔INDEX·TC 추적이 끊기면 고치고 재검증.
3. **갱신된 docs 분석** — 바뀐 REQ/IA/POL/SCR/glossary를 근거로 화면설계서에 반영할 변경점(화면별 mockup·정의·IA·권한표·용어)을 도출한다.
4. **화면설계서 갱신 → PDF 빌드** — docs를 단일 진실로 삼아 designspec의 mockup·정의·IA·권한표·용어를 갱신하고 `bash prototype/build-all.sh vX.Y` 로 PDF 생성.
5. **버전·개정 이력** — 버전 칩·푸터·프로토타입/PDF 참조를 vX.Y로 갱신. **개정 이력 표 행은 기획자가 관리** — 자동 추가 금지, 단 명시 승인 시 추가한다.

## 절차 B — 배포 후 다음 버전 라인 개시 (릴리스 컷)
> 배포한 vX.Y는 불변 동결, 오늘부터의 작업은 vX.Z 라인에 쌓이도록 분기한다. docs 동기화(절차 A)와 무관.

1. **배포본 동결 검증** — 라이브 `[DOMAIN] 화면설계서.designspec.html` 와 동결본 `_vX.Y.html` 가 **바이트 동일(md5)** 인지 확인. 다르면 배포 시점 스냅샷 누락 → 기획자에게 확인.
2. **`.baseline/` 무결성 복구** — `.baseline/[DOMAIN] 화면설계서.designspec.html` 를 배포 `_vX.Y.html` 로 갱신(md5 일치 검증). **베이스라인 소스는 배포 PDF와 항상 일치**해야 한다(자주 stale됨).
3. **다음 버전 라인 개시**
   - 프로토타입: `_vX.Y.html` → `_vX.Z.html` 복사, **자기 버전 푸터만** vX.Z로(파생 출처 주석은 보존).
   - 라이브 designspec: 버전 라벨을 vX.Z로 — **아래 '치환 규칙' 엄수**.
4. **동결본 불변** — `_vX.Y.html` · `_vX.Y.pdf` 는 어느 단계에서도 건드리지 않는다. PDF 빌드(`build-all.sh vX.Z`)와 푸터 날짜는 vX.Z 내용 확정 후.

### ⚠️ 버전 라벨 치환 규칙 (정밀 — 블랭킷 치환 금지)
designspec 안 `vX.Y` 를 일괄 치환(`sed s/vX.Y/vX.Z/g`)하면 역사 기록·화면 상태가 깨진다. **딱 3종만** 올린다:
- ✅ 커버 버전 칩 `<b>Version.</b> vX.Y`
- ✅ 페이지 푸터 버전 토큰 `[DOMAIN] 화면설계서 vX.Y ` (※ 푸터 **날짜는 그대로** — 빌드 시 갱신)
- ✅ 프로토타입 참조 `프로토타입_vX.Y.html`

**보존(절대 자동 변경 금지):**
- 🔒 화면 상태 칩 `vX.Y · 개정` — 화면별 *마지막 개정 버전*. 실제 개정한 화면만 기획자가 vX.Z로.
- 🔒 인라인 변경 기록 `…추가(vX.Y)` 등 — 그 버전에 일어난 사실.
- 🔒 파생 출처 주석(예: ADMIN 프로토타입의 "USER 프로토타입_vX.Y 구조 재사용").
- 🔒 개정 이력 표 행 — 기획자 직접 관리(절차 A·B 공통).

치환 후 **남은 `vX.Y` 수 = 상태 칩 + 역사 기록 수** 와 정확히 일치하는지 `grep` 으로 검증한다.

## 작업 리듬 (토큰·재작업 낭비 방지 — 2026-07-23 확정)
> 배경: 실제 운영에서 한 세션 PDF 중간 빌드 3회·완료 5~6회가 반복되고, designspec↔docs를 매 턴 양쪽 수정해 파상 확산이 발생했다. 아래 3가지로 고정한다.

1. **PDF 빌드 = 배포 행위.** 중간 검토는 designspec HTML을 브라우저로 본다. `build-all.sh`는 **리뷰/배포 확정 시점에만** 실행한다. 빌드 직전 "더 수정할 것 없나?" 한 번 확인.
2. **docs 동기화 시점 = 버전 컷 때 일괄.** 작업 중에는 designspec만 고치고, docs 반영은 절차 A에서 몰아서 한다.
   - **예외(즉시 반영):** `POL`·`glossary` — 판단 기준이므로 늦게 반영하면 그 사이 결정이 잘못된 전제 위에 쌓인다.
   - **필수:** designspec만 고친 변경은 아래 '알려진 미반영'에 **한 줄씩 즉시 기록**한다. 기억에 의존하면 드리프트가 재발한다.
3. **변경 요청은 '목표 상태 한 줄'로.** (예: "구기능 흔적 0 · 신기능 노출 전 문서") 그러면 1회 종합 패스로 끝난다. 부분 지시("A 삭제"→"B도"→"C도")는 같은 구간을 반복 재검증하게 만든다.

## 완료 체크리스트
> ⚠️ **체크리스트 SSOT = 본 문서. `.claude/skills/*/SKILL.md`의 체크리스트는 미러다 — 바꿀 때 둘 다 고친다.**
> (실행 시점에 실제로 읽히는 건 스킬 쪽이므로, 여기만 고치면 규칙이 반만 작동한다.)

**절차 A (버전 업데이트):**
- [ ] 프로토타입 변경분(용어·정책·요건·상태)이 docs에 모두 반영됐다
- [ ] '알려진 미반영' 목록을 소진했다 (남은 항목은 사유와 함께 유지)
- [ ] `scripts/check-docs.sh` ALL GREEN
- [ ] 화면설계서가 docs와 일치한다 (용어·권한·IA·화면 구성)
- [ ] **변경분이 해당 도메인의 모든 화면 × PC/모바일 목업에 반영됐다** (누락 상습 지점 — 대조 확인. 목업뿐 아니라 액션 정의·유효성·상태 매트릭스까지)
- [ ] 버전·참조·개정 이력·PDF가 갱신됐다

**절차 B (릴리스 컷):**
- [ ] **컷 직전 정합성 스윕** — check-docs + 개정이력↔목업 + PC↔모바일 대조 (드리프트를 다음 라인으로 넘기지 않는다)
- [ ] 라이브 == 동결본 `_vX.Y.html` md5 일치(배포 무결) 확인
- [ ] `.baseline/` 소스 = 배포본으로 갱신(md5 일치)
- [ ] 다음 버전 프로토타입 `_vX.Z.html` 개시(자기 버전 푸터만)
- [ ] designspec 버전 라벨 3종만 vX.Z (상태 칩·역사 기록·개정 이력 보존, grep 검증)
- [ ] 동결본 `_vX.Y.*` 무변경

## 알려진 미반영 (backlog — 다음 동기화 때 본 절차로 정리)
> designspec만 고치고 docs에 아직 반영하지 않은 변경을 **한 줄씩 즉시 기록**한다. 절차 A에서 소진한다.
