# 리뷰 모드 점검표

리뷰 모드에서는 이 파일을 항상 읽는다. 전 항목을 기계적으로 나열하지 말고, 기획안의 핵심 플로우에 적용해 **발견된 문제 중심**으로 보고하라. 각 항목의 괄호는 이론 근거 인용 키워드다.

## A. 개념 모델 일관성 (UCSD: 3모델)

- [ ] 이 서비스/기능의 디자인 모델을 한 문장으로 추출할 수 있는가? 못 하면 그 자체가 발견 사항이다.
- [ ] 화면·문구·동작이 모두 같은 모델을 암시하는가? 은유 충돌(폴더 vs 태그, 대화 vs 문서)이 없는가?
- [ ] 타깃 사용자가 기존 경험에서 가져올 멘탈 모델과 충돌하는 지점은? 충돌한다면 시스템 이미지가 재교육을 수행하는가?
- [ ] 명칭·레이블이 시스템 내부 용어가 아니라 사용자 언어인가? (의미적 거리)

## B. 실행의 간극 (UCSD: Gulf of Execution)

- [ ] 각 화면에서 "지금 할 수 있는 행동"이 보이는가? (시그니파이어)
- [ ] 사용자의 주 의도가 그 화면의 주 행동과 일치하는가? 주 행동이 시각적으로 우선하는가?
- [ ] 조작-결과의 매핑이 자연스러운가? (방향, 위치, 순서)
- [ ] 잘못된 행동이 애초에 불가능하게 제약되어 있는가, 아니면 에러로 처리하는가? (제약 > 에러)
- [ ] 행동 비용(단계 수, 입력량)이 과제 가치에 비례하는가? 저가치 과제에 고비용 플로우는 없는가?

## C. 평가의 간극 (UCSD: Gulf of Evaluation)

- [ ] 모든 사용자 행동에 즉각적 피드백이 있는가? (특히: 저장, 전송, 결제, 비동기 처리)
- [ ] 피드백이 해석 가능한가 — 무엇이, 왜, 다음은 무엇인지 담고 있는가?
- [ ] 시스템의 현재 상태(로딩, 진행률, 동기화 여부)가 항상 드러나는가?
- [ ] 과제 완료를 사용자가 확신할 수 있는 명시적 신호가 있는가?

## D. 오류 설계 (DOET: slip/mistake)

- [ ] 파괴적 행동(삭제, 전송, 결제)에 실행취소가 있는가? 확인창에만 의존하지 않는가?
- [ ] 예상되는 실수(slip): 인접 타깃 오터치, 습관적 확인 — 에 대한 방어가 있는가?
- [ ] 예상되는 착오(mistake): 기능 용도 오해 — 를 유발할 시스템 이미지 요소는 없는가?
- [ ] 오류 메시지가 사용자를 탓하지 않고 복구 경로를 안내하는가?

## E. 기억 부담 (DOET: 세상 속 지식)

- [ ] 사용자에게 기억을 요구하는 지점(코드, 이전 화면의 정보, 규칙)이 있는가? 재인으로 바꿀 수 있는가?
- [ ] 다단계 플로우에서 앞 단계 정보가 뒤 단계에 필요한 경우, 시스템이 대신 들고 가는가?

## F. 중단 내성 (UCSD: 활동 구조)

- [ ] 플로우 중간 이탈 시 입력이 보존되는가?
- [ ] 복귀 시 "어디까지 했는지"를 시스템이 알려주는가?
- [ ] 긴 과제가 중단 가능한 단위로 나뉘어 있는가?

## G. 선제적 도움 (UCSD: Answers First)

- [ ] 엠프티 스테이트가 "무엇을 하면 되는지"를 안내하는가?
- [ ] 사용자가 질문을 형성하기 전에 답이 배치되어 있는가? (예시, 플레이스홀더, 상황별 힌트)
- [ ] 도움이 필요한 순간에 도움이 그 자리에 있는가, 아니면 별도 메뉴로 숨어 있는가?

## H. 감성 수준 (Emotional Design: 3수준)

- [ ] 이 서비스의 승부 수준(본능/행동/반성)이 정해져 있고 설계가 그에 부합하는가?
- [ ] 첫 3초의 본능적 인상에 결격 사유가 없는가?
- [ ] 핵심 과제 완수 시 유능감을 주는가? (행동적)
- [ ] 계속 쓸·남에게 말할 이유가 있는가? (반성적)
- [ ] 불안·조급함을 이용한 다크 패턴이 없는가?

## I. 현 시점 트렌드 항목 (해당 요소가 있을 때만 — 상세는 ux-trends-2026.md)

- [ ] AI 기능: 결과의 근거 설명, 사용자 언어의 결정 설명, 수정/거부 경로가 있는가? (설명 없는 AI 출력 = 평가의 간극 차단급)
- [ ] 에이전트/자동화: 진행 상태 가시성, 중단·회수 수단, 사용자의 통제감이 유지되는가?
- [ ] 개인화: 무엇을 기반으로 하는지 설명 가능하고, 사용자가 조절/해제할 수 있으며, 그 설정이 발견 가능한가?
- [ ] 멀티모달/음성: 모달리티별로 실행·평가 간극을 따로 점검했는가? 음성의 "무엇을 말할 수 있는지" 안내가 있는가?
- [ ] 크로스플랫폼: 기기 전환 시 입력 보존·진행 위치 복원·개념 모델 일관성이 명세되어 있는가?
- [ ] 접근성: 인지 부하, 모션 감쇠, 대비, 대체 입력이 기획 요구사항에 포함되어 있는가? (QA 체크박스가 아니라)
- [ ] 마이크로인터랙션: 상태 변화의 피드백이 기획 명세에 있는가? 과잉 모션의 접근성 충돌은 없는가?

## 심각도 분류

- **차단**: 사용자가 과제를 완수할 수 없거나, 완수 여부를 알 수 없음 (주로 B·C의 실패)
- **마찰**: 완수는 하지만 불필요한 비용·불안 발생 (주로 D·E·F의 실패)
- **개선 기회**: 기능적으로 문제없으나 매력·애착·재사용 동기 부재 (주로 G·H)
