# spec-self-review — 기획 문서 셀프 검토 (Phase 2)

> 단일 진실: [`rules/methodology/README.md`](../../../rules/methodology/README.md) "Phase 2 — 셀프 검토".
> 원칙: **추측해서 채우지 않는다.** 실제 적혀 있지 않은 것은 "적혀 있지 않음"으로 표시한다.

## 언제
기능·버전 마감 전, 또는 사용자가 문서 점검을 요청할 때. 산출물 배포 전 품질 게이트.

## 절차
### 1. 기계 검증 먼저 (1초)
```bash
bash scripts/check-docs.sh
```
ID 포맷·본문↔INDEX 동기화·중복 ID·추적 끊김(REQ↔SCR↔TC)·화면설계서 버전 정합을 자동 점검한다. 여기서 잡히는 건 사람이 읽기 전에 고친다.

### 2. 7개 항목 정독 점검
관련 docs를 읽고, 각 지적을 **구체적 위치(파일·줄)** 와 함께 낸다:
1. **미정의 용어** — `glossary.md`에 없는데 본문에 쓰인 단어
2. **문서 간 모순** — 같은 항목이 서로 다른 값/규칙으로 적힌 곳
3. **빠진 상태** — 정상 외 로딩·빈·에러·권한·오프라인 정의 여부(`N/A` 명시 OK)
4. **빠진 범위** — Out of scope에 명시 안 된 모호한 영역
5. **검증 불가 표현** — '빠르게·자연스럽게·직관적으로' 류 막연한 말 → 숫자·동작으로
6. **빠진 비기능** — 성능·접근성·보안·다국어·데이터 보관/삭제
7. **추적 끊김** — REQ ↔ SCR ↔ TC 매핑이 빠진 항목

### 3. 등급화 + 기록
지적을 🔴 결정 필요 / 🟡 보강 / 🟢 경미 로 등급화한다. 결과를 `docs/REVIEW.md`(없으면 생성)에 **일자별 누적** 기록한다. 처리되면 상태를 🟩 로 갱신.

## 경계 (사람 vs AI)
- AI = 구멍·모순·추적 끊김 **탐지** + 기계 검증.
- 사람(기획자) = 🔴 결정 필요 항목의 **판단**, 카피·콘텐츠 작성.
- 추측으로 빈칸을 메우지 않는다 — 모르면 "적혀 있지 않음"으로 남기고 묻는다.
