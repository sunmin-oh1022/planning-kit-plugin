# intent-capture — 기획 의도 캡처 (Phase 1 앞단)

> 단일 진실: [`rules/methodology/README.md`](../../../rules/methodology/README.md) 6 Phase — 본 스킬은 **Phase 1(기획 문서 작성) 바로 앞**에서 도는 준비 단계다. "말 한 줄 → 바로 docs" 사이의 빈칸(의도 구체화)을 채운다.
> 핵심 규칙: **의도·판단·콘텐츠 결정은 사람. 질문 설계와 초안 정리는 AI.** 추측으로 빈칸을 메우지 않는다 — 모르면 묻고, 사람이 "Decide for me"를 고를 때만 AI가 근거와 함께 제안하되 최종 승인은 사람이 한다.

## 언제
- 만들고 싶은 게 **말 한 줄**로만 있고 아직 docs 초안이 없을 때 (새 기능·새 제품·새 도메인 착수).
- 기존 기능을 **고도화**하려는데 방향이 아직 흩어져 있을 때.
- 사용자가 "질문해줘 / 구체화해줘 / 의도 잡아줘"라고 요청할 때.

이미 배포된 docs의 구멍·모순을 점검하는 단계가 아니다(→ `spec-self-review`). 여기는 **아직 적히지 않은 것을 사람에게서 끌어내 초안으로 만드는** 단계다.

## 절차

### 1. 씨앗 + 맥락 읽기 (묻기 전에)
사용자의 한 줄 아이디어를 받고, **먼저 기존 맥락을 읽는다** — `docs/PRD.md`·`docs/glossary.md`·`docs/REQ.md`·`ROADMAP.md`. 이미 정해진 것은 다시 묻지 않는다(추측 금지 원칙의 짝: **이미 있는 걸 되묻지도 않는다**). 무엇이 비어 있는지로 질문 목록을 만든다.

### 2. 구조적 Q&A — AskUserQuestion 웨이브
비어 있는 축을 **넓은 맥락 → 구체 검증** 순서로 좁혀가며 묻는다(문서 4단 체계와 같은 방향). 한 번에 한 웨이브(최대 4문항). 질문 설계 규칙은 아래 [§ 질문 설계](#질문-설계-핵심) 참조. 한 웨이브가 끝나면 답을 반영하고, 아직 빈 축이 남았으면 다음 웨이브를 던진다.

### 3. 종합 → docs 초안 반영
답변을 5대 원리(단일 진실·ID 추적·모든 상태·Out of scope·GWT)에 맞춰 아래 [§ 초안 반영](#초안-반영-어느-답이-어느-문서로) 표대로 각 문서에 **초안(`status: draft`)** 으로 적는다. 값은 한 곳에만(단일 진실), 나머지는 ID 참조. 사람이 확정 안 한 자리는 `*(TODO)*` 로 남기고 채우지 않는다.

### 4. 검증
```bash
bash scripts/check-docs.sh
```
ID 포맷·본문↔INDEX 동기화·추적 끊김(REQ↔SCR↔TC)을 점검한다. 초안 단계라 🟡 경고는 자연스럽다(아직 채우는 중). 🔴 는 고친다. 이어서 사람에게 "이 초안 방향이 맞나요? 어디를 바꿀까요?"로 확인받는다.

### 5. 기록
그날 캡처한 의도·결정(특히 "Decide for me"로 AI가 제안하고 사람이 승인한 것)을 `DEVLOG.md` 에 남긴다. Phase 1(정식 기획 문서 작성)으로 넘어갈 준비 완료.

## 질문 설계 (핵심)
이 스킬의 심장. 첨부된 Claude Design 질문 UI를 **AskUserQuestion으로 재현**한다.

**한 웨이브 = 최대 4문항.** 각 문항은:
- **옵션 칩 2~4개** — 서로 배타적인 선택지. 라벨은 1~5단어로 짧게.
- **"Decide for me" 옵션 포함** — 고르면 AI가 근거와 함께 제안(라벨 끝에 `(추천)`, 목록 맨 앞). 사람이 판단을 떠넘길 자리를 항상 열어둔다.
- **"Other" 자유입력은 넣지 않는다** — 도구가 자동으로 붙여준다. 직접 옵션에 만들지 말 것.
- **여러 개가 동시에 참이면 `multiSelect: true`** — 예: "주요 동작"(편집·복사·저장·공유), "타겟 플랫폼".
- **레이아웃·구조를 비교시켜야 하면 `preview`** — 옵션마다 ASCII 목업/코드 스니펫으로 나란히 보게. 단순 선호 질문엔 쓰지 않는다.

**무엇을 묻나 — 문서 4단 체계에 매핑** (넓은 맥락 → 구체 검증 순):

| 질문 축 | 예시 질문 | 흘러갈 문서 |
| --- | --- | --- |
| 대상·문제 | "핵심 사용자는? / 어떤 불편을 푸나?" | PRD (기본 정의) |
| 범위 | "이번에 **안 할** 것은? (Out of scope)" | PRD (In/Out/Backlog) ★ |
| 핵심 동작·우선순위 | "가장 자주 쓸 동작을 순서대로" (multiSelect) | REQ (MoSCoW) |
| 규칙·제약·예외 | "지켜야 할 제약/금지는? 예외 처리는?" | POL (사유+시점) |
| 용어·표기 | "이 개념을 뭐라 부르나? 타입·범위는?" | glossary |
| 상태 | "로딩·빈·에러·권한·오프라인 중 필요한 건?" (multiSelect) | SCR (상태 매트릭스) |
| 검증 기준 | "성공/실패를 무엇으로 판정하나?" | TC (GWT) |
| 비기능 | "성능·접근성·보안·다국어·데이터 중 이번 대상은?" (multiSelect) | PRD (비기능) |

**규칙:**
- **이미 답이 있으면 묻지 않는다.** docs·대화에 있으면 건너뛴다.
- **막연한 답은 되묻는다.** "빠르게/직관적으로"가 나오면 숫자·동작으로 좁히는 후속 질문(5대 원리 ⑤ GWT).
- **Out of scope를 반드시 한 번은 묻는다.** 좁힐수록 빠르다(원리 ④).
- 사람이 "Decide for me"를 고르면 → AI가 **근거 한 줄과 함께** 값을 제안하고, 다음 확인 때 사람이 뒤집을 수 있게 남긴다.

## 초안 반영 (어느 답이 어느 문서로)
답변을 아래대로 **초안**으로 정리한다. 포맷은 각 문서 상단의 예시 행(*기울임*)과 헤더 규약을 그대로 따른다.

| 답변 | 문서 | 초안 형태 |
| --- | --- | --- |
| 대상·문제·가치·마일스톤 | `docs/PRD.md` | 기본 정의 표 채움 |
| In/Out/Backlog | `docs/PRD.md` | 범위 표 — **Out of scope 우선** |
| 핵심 동작 | `docs/REQ.md` | 표 행 + `### REQ-### ` 헤더(status: **draft**, priority MoSCoW, related) |
| 규칙·제약·예외 | `docs/POL.md` | 표 행 (사유 + 적용 시점 필수) |
| 용어 | `docs/glossary.md` | 표 행 (타입·범위 = 단일 진실) |
| 상태 | `docs/screens/SCR-###.md` | 상태 매트릭스 6개(해당 없으면 `N/A` 명시) |
| 검증 기준 | `docs/TC.md` | Given–When–Then |

- **status는 `draft`** 로 시작한다(정식 승인 전). ID는 `INDEX.md` 최대값 +1(대규모는 `indexing.md § 1`).
- 값은 **한 곳에만**. glossary에 "닉네임 2–12자"를 적었으면 POL·REQ는 그 값을 다시 쓰지 않고 glossary를 가리킨다.
- 사람이 아직 정하지 않은 칸은 `*(TODO)*` — AI가 그럴듯하게 채우지 않는다.

## 경계 (사람 vs AI)
- **AI** = 무엇이 비었는지 탐지 · 좋은 질문 설계(칩·다중선택·preview) · 답을 초안으로 정리 · 정합성 기계 검증.
- **사람(기획자)** = 무엇을·왜 만들지 판단 · 정책과 콘텐츠 확정 · "Decide for me"로 AI가 낸 제안의 최종 승인 · 초안을 정식(reviewed/approved)으로 올릴지 결정.
- 추측으로 빈칸을 메우지 않는다. 모르면 "적혀 있지 않음"으로 남기고 묻는다.

## 완료 체크리스트 (Phase 1 넘어가기 전)
- [ ] 대상·문제·**Out of scope** 가 PRD 초안에 적혔다
- [ ] 핵심 동작이 REQ 초안(status: draft) + MoSCoW 우선순위로 적혔다
- [ ] 새로 나온 용어가 glossary에 타입·범위와 함께 들어갔다
- [ ] 막연한 표현('빠르게·직관적으로')이 숫자·동작으로 좁혀졌다
- [ ] 같은 값이 두 문서에 중복되지 않았다(한쪽은 ID 참조)
- [ ] `bash scripts/check-docs.sh` 의 🔴 가 없다
- [ ] 사람이 초안 방향을 확인했고, DEVLOG에 남겼다
