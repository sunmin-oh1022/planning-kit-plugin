# common.md — UX 공통 원칙 (플로우 무관)

플로우 · 플랫폼과 무관하게 화면 작업 어디에나 적용되는 보편 원칙. 플로우별 규칙은 [`flows/`](flows/) 아래에서 확장한다. 시각 토큰은 (TODO 스타일 정의 문서), View 구조는 [`../ui.md`](../ui.md).

수치 근거: WCAG 2.2 · Apple HIG · Material Design 3 — 플랫폼별 가이드는 본 프로젝트의 타깃 환경에 맞춰 채워 쓴다.

## 1. 입력 요소는 오동작 없이 누를 수 있게
탭·클릭 가능한 요소는 사용자의 입력 수단(손가락·마우스·포커스)으로 정확히 짚을 수 있어야 한다.

- 최소 타깃 크기: 터치는 44×44 CSS px 이상(WCAG 권장), 데스크톱·웹은 24×24 CSS px 이상이 WCAG 2.2 AA. 크기뿐 아니라 요소 간 **간격(8px 이상)** 도 확보한다.
- 디자인상 시각 요소가 작으면 보이지 않는 패딩으로 입력 영역을 확장한다 (아이콘 버튼·체크박스 특히 주의).
- 키보드 포커스도 같은 영역을 갖도록 한다 (탭 이동 시 포커스 링이 정확히 잡혀야 함).

**점검**: 가장 작은 입력 요소가 최소 타깃 크기를 만족하고, 인접 요소와 충분히 떨어져 있는가?

## 2. 모든 동작에 즉각 피드백을 준다
입력에 아무 반응이 없으면 사용자는 고장났다고 느낀다.

- 누르는 즉시 눌림 상태(밝기·스케일 변화 등)로 반응한다. 입력 수단별로 hover·focus·active 상태를 모두 정의한다.
- 비파괴적 동작은 즉시, 파괴적·시간이 걸리는 동작은 진행 상태를 보여준다.

**점검**: 모든 입력에 0.1초 안에 시각적 반응이 있는가? 입력 수단(터치·마우스·키보드)별 상태가 모두 정의되어 있는가?

## 3. 체감 속도를 설계한다
실제 속도보다 '느껴지는 속도'가 경험을 좌우한다.

- 로딩은 빈 화면·스피너 대신 콘텐츠 형태의 스켈레톤으로 채운다.
- 좋아요·토글처럼 가벼운 동작은 낙관적 UI로 — 즉시 성공 상태로 바꾸고, 백엔드 실패 시에만 원래 상태로 롤백한다.
- 응답 지연 임계를 의식한다: 즉각 <0.1s · 끊김 없는 흐름 <1s · 주의 유지 <10s.

**점검**: 데이터 로딩 중 화면이 비거나 멈춰 보이지 않는가?

## 4. 로딩만이 아니라 '모든 상태'를 디자인한다
한 화면에는 정상 외에도 로딩·빈 상태·에러·성공·권한 거부·오프라인이 있다.

- 빈 상태에는 다음 행동을 제시한다 ("아직 없습니다"로 끝내지 않는다).
- 에러에는 무엇을 하면 되는지를 알려준다 ("오류가 발생했습니다"·에러 코드만 띄우지 않는다).

**점검**: 데이터 0건 · 네트워크 실패 · 권한 거부 · 오프라인 상태를 각각 그렸는가?

## 5. 환경의 물리·논리 구조를 존중한다
화면의 안전 영역과 사용자의 조작 컨텍스트를 침범하지 않는다.

- 시스템 UI(상태 바·내비게이션 바·노치·홈 인디케이터·브라우저 크롬 등)에 콘텐츠가 가리지 않게 한다.
- 헤더·하단 바·플로팅 요소는 안전 영역(safe area / viewport inset)을 침범하지 않는다.
- 가로·세로 회전, 창 크기 변화, 키보드 출현 등 레이아웃 변동을 가정한다.

**점검**: 다양한 화면 크기·해상도·시스템 UI 환경에서 잘리는 요소가 없는가?

## 6. 접근성을 기본값으로 둔다
처음부터 모두가 쓸 수 있게 만든다 — 나중에 붙이지 않는다.

- 글자는 고정 픽셀이 아니라 사용자의 시스템 글자 크기 설정에 따라 스케일되게 한다 (상대 단위·동적 폰트).
- 스크린리더 라벨을 제공하고, 색만으로 정보를 전달하지 않으며, 대비는 4.5:1(큰 텍스트·UI 요소는 3:1)을 지킨다.
- **동작 줄이기(reduce motion)** 와 다크 모드(시스템 테마)를 지원한다.
- 키보드만으로 모든 기능에 접근할 수 있게 한다 (포커스 순서·이스케이프 경로).

**점검**: 시스템 글자 크기를 최대로 키워도 레이아웃이 깨지지 않는가? 키보드만으로 모든 동작을 수행할 수 있는가?

## 7. 일관성과 플랫폼 관습을 따른다
타깃 환경의 관습을 거스르지 않는다. 같은 것은 어디서나 같게.

- 성공·경고·오류 등 의미론적 컬러를 시스템 전체에서 일관되게 쓴다.
- 내비게이션은 예측 가능하게 한다 (되돌아가기 명확, 주 탐색 항목 수 제한).
- 디자인 토큰(색·간격·타이포)으로 통일하고, 타깃 환경의 시스템 컴포넌트·아이콘 셋을 우선한다.

**점검**: 새 사용자가 학습 없이 다음 행동을 예측할 수 있는가?

## 8. 콘텐츠 우선, 군더더기 최소
사용자의 콘텐츠가 먼저 보이고, UI는 필요할 때 드러난다.

- 화면을 열면 '내 것(콘텐츠)'이 먼저 보여야 한다 — 제품의 인터페이스가 아니라.
- 애니메이션은 목적이 있고 빠르게. 입력은 최소화한다 (적절한 입력 컴포넌트·인라인 검증).

**점검**: 첫 화면에서 사용자가 곧장 핵심 콘텐츠·행동에 닿는가?
